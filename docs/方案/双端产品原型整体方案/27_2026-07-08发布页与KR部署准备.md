# 2026-07-08 发布页与 KR 部署准备

## 目标

先做一个公开发布页，职责只包括项目介绍和 Android APK 下载。图片登记网页、个人管理后台、API 管理和运营配置不放进这个页面。

当前公开名称使用暂名 `Lumo Shelf`。正式命名确认后，应同步替换页面标题、下载文件名、镜像名、仓库名和域名。

## 当前 APK 状态

当前包来自：

```text
android/app/build/outputs/apk/debug/app-debug.apk
```

它只能被标为内部测试/debug 包。公开传播前更好的做法是生成 release 自签包，并明确：

- 版本号
- SHA256
- 签名方式
- Android 最低版本
- 是否需要手动允许安装未知来源
- 已知风险或限制

## 域名

默认模板使用：

```text
shelf.lumokato.com
```

这是暂定值，不代表最终产品名。可替换候选包括：

- `dolls.lumokato.com`
- `lumo-dolls.lumokato.com`
- `checkin.lumokato.com`

修改域名只需要调整 Portainer stack env 中的 `LUMODOLL_RELEASE_HOST`。

## 构建镜像

在项目根目录执行：

```powershell
rtk docker build -f ops/release-page.Dockerfile -t lumodoll-release:local .
```

如果要推送 GHCR：

```powershell
rtk docker tag lumodoll-release:local ghcr.io/lumokato/lumodoll-release:latest
rtk docker push ghcr.io/lumokato/lumodoll-release:latest
```

GHCR repo 是否公开要单独确认。发布页源码适合公开，但 APK 是否放在镜像或 release artifact 中，需要按测试范围决定。

## Portainer 部署

在 Portainer 新建或更新 stack：

- Compose file：`ops/compose.release.kr.yml`
- Env：参考 `ops/lumodoll-release.kr.env.example`
- `NETWORK_NAME=proxy-kr`
- `LUMODOLL_RELEASE_HOST=shelf.lumokato.com`
- `TRAEFIK_CERTRESOLVER=cloudflare`
- `LUMODOLL_RELEASE_IMAGE=ghcr.io/lumokato/lumodoll-release:latest` 或服务器本地镜像名

确认 `proxy-kr` 已存在，Traefik 已接入 Cloudflare 证书解析器。

## 验证

部署后验证：

```bash
rtk curl -I https://shelf.lumokato.com/
rtk curl -I https://shelf.lumokato.com/public/downloads/lumo-shelf-android-debug.apk
```

浏览器检查：

- 第一屏显示 `Lumo Shelf`、下载按钮和“最新界面截图待补”。
- 页面不出现 API key、R2、数据库、服务器内网地址或测试域名。
- 下载链接返回 APK，大小约 47 MiB。
- 移动端文字不溢出。

## 回滚

Portainer 中回滚 stack image 到上一 tag，或临时下线发布页 router。发布页不持久化数据，回滚只影响静态页面和下载文件。

3. 重建发布页容器后，检查 Traefik 日志不再出现 `failed to find zone lumokato.com`。
